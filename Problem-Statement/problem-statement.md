# Problem Statement & User Persona

## Problem Statement

Cloud security teams using a CNAPP (Cloud-Native Application Protection Platform) receive a high volume of alerts every day, including misconfigurations, IAM risks, and exposed resources across multiple AWS and GCP accounts.

Most alerts are not equally urgent, making it difficult for security engineers to identify the issues that require immediate attention. This creates alert fatigue, increases investigation time, and slows down remediation.

## User Persona

### Riya — Security Engineer

Riya is a security engineer responsible for monitoring and managing security across approximately 15 cloud accounts on AWS and GCP.

### Goals

* Quickly identify high-risk and critical alerts.
* Understand the impact of an alert without checking multiple cloud consoles.
* Resolve or dismiss alerts efficiently.
* Maintain an audit trail for security and compliance reviews.

### Pain Points

* Large numbers of low-priority alerts make critical issues difficult to identify.
* Limited visibility into the potential blast radius of an alert.
* Investigation context is scattered across different tools.
* Repetitive manual remediation takes time.

### Key User Need

Riya needs a **focused alert triage workflow** that helps her quickly understand **what is dangerous, why it matters, and what action to take next**.
